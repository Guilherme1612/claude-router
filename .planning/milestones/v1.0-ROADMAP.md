# Roadmap: Claude Router

**Project:** Claude Router — global `~/.claude` always-on prompt-routing framework
**Core Value:** Every user prompt routed to the right workflow mode + skills + agents automatically, in <100ms with no external API call — so rework from mis-routed tasks drops without a per-prompt LLM tax.
**Granularity:** Standard
**Phase ID convention:** Sequential
**Coverage:** 30/30 v1 requirements mapped (HOOK 4, RTE 7, INJ 6, GRD 5, COX 3, MAN 2, TEL 3, GRF 2, VRF 2). v2 (EVO 3, ANC 1) scheduled into Phases 3 and 4 respectively.

> **Load-bearing correction (applied throughout):** A `UserPromptSubmit` hook can ONLY append `additionalContext` (model-read). The harness does NOT auto-run appended slashes — the MODEL executes every channel (runs the slash, or invokes the `Skill`/`Agent` tool). "High-confidence auto-invoke" in this roadmap means a strong model instruction, not harness execution.

## Phase Details

### Phase 1: Router Core (closed loop + mode-map + calibration gate)

**Goal:** Every user prompt is classified, tiered, injected, cached, logged, and guarded by a single stdlib-only `UserPromptSubmit` hook that fails open in <100ms, coexists with caveman, and routes the right mode + skills + agents on ≥8/10 of a user-approved 10-task calibration test.
**Mode:** mvp
**Depends on:** Nothing (first phase)
**Requirements:** HOOK-01, HOOK-02, HOOK-03, HOOK-04, RTE-01, RTE-02, RTE-03, RTE-04, RTE-05, RTE-06, RTE-07, INJ-01, INJ-02, INJ-03, INJ-04, INJ-05, INJ-06, GRD-01, GRD-02, GRD-03, GRD-04, GRD-05, COX-01, COX-02, COX-03, MAN-01, MAN-02, TEL-01, TEL-02, TEL-03, GRF-01, VRF-01, VRF-02
**Success Criteria** (what must be TRUE):

  1. On any input (empty, trivial, malformed, or a forced throw), the hook returns the original prompt unchanged within <100ms warm latency and ≤500 injected tokens — routing never blocks a prompt (fail-open verified).
  2. A user-reviewed `mode-map.json` spans the full command inventory (gsd + superpowers + modernize + git + hookify + scaffold + design + ralph-loop) with `invoke_kind` per entry, and the model runs the suggested mode / invokes the Skill or Agent tool from the injected instruction at High tier (reasoning line visible); Medium tier primes without auto-action; Low tier passes through untouched.
  3. Guards hold end-to-end: explicit `/`-prefix or known-name prompts short-circuit to pass-through (`user_explicit` logged); MCP-missing agents demoted to `warn`; project-scoped skills filtered out globally; ralph-loop routed only when genuine verifiable done-criteria exist (no fabricated promise); deny-rule paths never referenced.
  4. Telemetry is append-only with hash-only prompt signatures (never raw prompt), `0600` perms, atomic writes, and carries `outcome` + `downstream_invocations` fields from day 1 (unpopulated) — Phase 3 needs no schema migration.
  5. The `settings.json` binding is append-only with a before/after diff audit showing ONLY the new `UserPromptSubmit` entry (16 existing hooks + statusline + 4 enabled plugins intact), caveman still fires, and the 10-task calibration test passes ≥8/10 right picks (tuning `T_high`/`T_low`/`M` in `mode-map.json` is a data edit, no redeploy).

**Phase note (internal sub-sequencing — not separable shippable phases):**

1. Hook skeleton + fail-open smoke test (empty-input + forced-throw return original).
2. Explicit-override short-circuit + sentinel + caveman coexistence (read `caveman-mode-tracker.js` to finalize sentinel).
3. BM25 + mode-map + injection formatting (`formatInjection(route)` with per-`invoke_kind` unit tests — the hook-contract correction bites hardest here).
4. MCP guard + scope filter + ralph-loop two-gate (hard-filter at candidate collection; quote completion-promise, never synthesize).
5. Telemetry-privacy invariants (hash-only, `0600`, deny-rule respect, secret-pattern redaction before hashing).
6. 10-task calibration gate (dry-run, log full score distribution, tune thresholds to ≥8/10).
7. `settings.json` append-only install with before/after diff audit — LAST action.

### Phase 2: Graphify Integration

**Goal:** Codebase-touching prompts route with real structural context folded into the routing + injection decision, replacing the Phase-1 graphify stub body without re-architecting the pipeline.
**Mode:** mvp
**Depends on:** Phase 1 (uses the Phase-1 graphify stub at pipeline step [11] as the insertion seam)
**Requirements:** GRF-02
**Success Criteria** (what must be TRUE):

  1. When the heuristic fires AND `graphify-out/` exists for cwd, the router queries the graph and folds structural context into routing + injection; when no graph exists, it skips and logs `graph_missing` (Phase-1 stub behavior preserved as the fallback).
  2. The graphify context contribution is capped (top-K symbols, ≤150 tokens) separate from the route block, so the per-prompt injection stays ≤ ~500 tokens total.
  3. On any graph error, the router fails open and routes on manifest alone — graphify integration never blocks a prompt.
  4. Measurably fewer mis-routes than Phase 1 on codebase-touching prompts (re-run the calibration test extended with codebase tasks; right-pick rate improves over Phase 1's baseline).

### Phase 3: Evolution

**Goal:** The router measurably improves its own routing accuracy over a ~2-week usage window with no manual `mode-map.json` edits, via weighted BM25 + outcome-feedback + map-mutation proposals.
**Mode:** mvp
**Depends on:** Phase 1 telemetry schema (carrying `outcome` + `downstream_invocations` from day 1) AND a ~2-week accumulated-telemetry usage window. **Sequence after a usage window, not strictly after Phase 2** — Phase 2 finishing does not make Phase 3 ready.
**Requirements:** EVO-01, EVO-02, EVO-03
**Success Criteria** (what must be TRUE):

  1. `weights.json` weighted BM25 boosts modes/skills/agents that led to clean runs (downstream `gsd-verify`/`gsd-ship` = good) and decays ones that led to rework (`gsd-debug`/`gsd-undo`/`gsd-forensics` fired shortly after = bad; next prompt continues same task = good) — outcome feedback verifies actual downstream Skill/Agent tool invocation, not just that injection happened.
  2. Routing accuracy improves AND cache hit rate rises over a 2-week window with no manual `mode-map.json` edits (telemetry shows the trend; weights + map mutations account for the improvement).
  3. `mode-map.json` mutation proposals are generated from telemetry pattern detection and either auto-applied or human-gated (the auto-apply vs human-approve split is an open v2/v3 design decision resolved here); drifted entries are auto-pruned.
  4. Telemetry rotation/compaction is in place as the log grows — no unbounded disk growth.

### Phase 4: Ancestor Reuse

**Goal:** The router reuses ≥1 existing discovery primitive (`gsd-surface` profiles, `find-skills`, or `claude-automation-recommender`) instead of duplicating its inline discovery logic, with no routing regression.
**Mode:** mvp
**Depends on:** Phase 1 `mode-map.json` existing (so the router knows what to reuse toward). **Parallelizable with Phases 2 and/or 3** — independent of graphify and evolution work.
**Requirements:** ANC-01
**Success Criteria** (what must be TRUE):

  1. At least one existing primitive (gsd-surface / find-skills / claude-automation-recommender) is reused instead of reimplemented — the inline discovery step at pipeline step [7] is swapped for the reuse path.
  2. No redundant discovery code remains in the router; the reuse path is the single source for that sub-job.
  3. Routing accuracy on the calibration test does not regress versus the pre-swap baseline (validated against accumulated telemetry before ripping out inline discovery).
