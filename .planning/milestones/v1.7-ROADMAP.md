## Phase Details

### Phase 47: Dispatch and Storage Safety

**Goal**: Claude and Codex execute durable work at most once while enforcing resource bounds and containing private lease and receipt state.
**Depends on**: Phase 46
**Requirements**: SAFE-01, SAFE-02, SAFE-03, SAFE-04, SAFE-05
**Success Criteria** (what must be TRUE):

  1. Repeated prompts, workers, compaction, and process restarts cannot execute the same durable work identity more than once in either runtime.
  2. A Claude or Codex child that exceeds its declared timeout, retry, output, or completion bound is stopped and records a truthful bounded outcome.
  3. Malformed or escaping lease and receipt identities are rejected, while accepted state remains beneath runtime-owned roots with private permissions.
  4. Concurrent lease creation and checkpoint updates cannot overwrite authority state, and both runtimes resume the same durable checkpoint at most once.

**Plans**: 3 (completed)

### Phase 48: Production Integration

**Goal**: Installed Claude and Codex runtimes use proportional strategy, safe learning, and durable migration on the real production dispatch path.
**Depends on**: Phase 47
**Requirements**: PROD-01, PROD-02, PROD-03, PROD-04, PROD-05
**Success Criteria** (what must be TRUE):

  1. Production dispatch selects and applies a validated proportional strategy before invoking native Claude or Codex work.
  2. Fresh Claude and Codex installations load dispatch, strategy, learning, migration, and every required dependency and complete the same end-to-end workflow.
  3. Duplicate receipts cannot satisfy learning thresholds, and learned changes cannot alter authority, risk, permission, or protected effects.
  4. Interrupted migration recovers repeatedly to a complete old or new generation, including when its active pointer is missing or corrupt.
  5. Release eligibility is derived from fresh, version-bound checks executed independently against each installed runtime rather than caller-supplied claims.

**Plans**: 3 (completed)

### Phase 49: Validation and Release Integrity

**Goal**: The repository is releasable only when deterministic tests, installed runtimes, validation evidence, planning projections, archive, and tag agree.
**Depends on**: Phase 48
**Requirements**: REL-01, REL-02, REL-03, REL-04, REL-05
**Success Criteria** (what must be TRUE):

  1. Focused and full repository runs repeatedly pass the current lifecycle, uninstall, lease, watcher-cleanup, performance, receipt, and dispatch contracts.
  2. Phases 47-49 each have executable Nyquist validation and current verification evidence with one unambiguous result.
  3. One automated release gate checks focused and full tests, installed-runtime parity, archive visibility, and canonical planning projections.
  4. Milestone audit, ROADMAP, STATE, REQUIREMENTS, installed bundles, archive artifacts, and release tag identify the same verified commit before v1.7 is declared shipped.

**Plans**: 3 (completed)
