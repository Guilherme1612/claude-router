<objective>
Ship the end-to-end tracer slice for Phase 23: a single "go to the next phase" prompt, classified as execute, resolved against fresh authoritative state to one contract-passing installed capability, with a safe-only approval pass-through and a framework-neutral next-prompt. Then expand the intent classifier to its full 8-disposition matrix with unit coverage.

Purpose: Prove the 8-layer pipeline (intent → action → state → transition → capability → approval → closure → next-prompt) end-to-end on the agent's earliest tokens, so the architectural decision (intent and approval are distinct from eligibility) is validated before horizontal expansion.
Output: Four new minimal-but-production modules, one end-to-end integration test, the intent classifier unit matrix, and the inventory-fixture extension with `workflow_transitions` contract envelopes.
</objective>

<assumption_delta_decision>
Phase 23 pluralizes dispatch authority: previously a capability was `dispatchable` (single boolean from `evaluateEligibility`), now it is `(eligible, intent_permits, state_permits, approval_grants)` — four independent gates. Decision: **promote** the new four-gate model to primary; `evaluateEligibility`'s `eligible` becomes one input (eligibility), not the whole decision. Rationale: EXEC-05 explicitly composes fresh-state + one-transition + healthy-deps + valid-args + permission + gates, and EXEC-07 requires approval *distinct* from execute intent — both force the generalization. Demoting the old single-boolean to one gate (not adding alongside) avoids a silent contradiction. No invariant test added here; the dispatch-integration tests in Plan 03 encode it.
</assumption_delta_decision>

| user prompt → classifier | Untrusted natural-language text enters the dispatch pipeline here |

| action mapper → registry | Framework-neutral contract read; must not fall back to hardcoded names |
| approval gate → dispatch | Destructive/privileged actions require a separately bound token |
