## The schema-v4 resolve contract (this phase's design deliverable)

- `mode-map.json` gains `"schema_version": 4`.
- Each `slash` entry may carry an optional `resolve` array: `[{ "name": "/gsd-debug", "weight": 1.0, "note": "..." }, ...]`. `name` is a **framework-neutral** candidate (may be a `/command`, a bare multi-token command, or a capability-role name). `entry.mode` remains the preferred (top) candidate but is now ALSO subject to presence — that is what closes the hole.
- Resolve decision (exported helper, e.g. `resolveSlashRoute(entry, indexes)`):
  1. Candidate set = `[mode (weight 1.0)] + entry.resolve[]` (dedup by stripped name).
  2. `present = candidates.filter(c => indexes.commands.has(stripLeadingSlash(c.name)))`.
  3. Return the first candidate in `present` ordered by descending weight (via stable sort), else `null`.
  4. **The matcher must NOT hardcode any framework prefix** (`gsd-`, `superpowers`, etc.). It reads candidates purely from the entry. The 32-01 Group B assertion enforces this.
- Guard-hole closure: a slash route is considered valid/interntional ONLY if `indexes.commands.has(mode)` OR `resolveSlashRoute` returns a present member. The blanket `mode === id && schema_version` pass is removed.
