<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| strategy/replan evidence → lease checkpoint state | Failure evidence and replacement work must be tied to the current lease/strategy and cannot erase completed claims. |
| strategy contract → Claude/Codex adapter | Untrusted plan data reaches native dispatch and must remain behind invocation and pre-dispatch validation. |
| adapter → host process | Native spawn can cause effects; resource, path, runtime, permission, timeout, retry, output, and completion gates must all remain active. |
| durable lease state → resume | On-disk state may be stale or tampered and must not authorize a missing/blocked claim or cross-scope resume. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-05 | Tampering/Elevation | `replanStrategy()` | high | mitigate | Bind failure evidence to the current strategy identity, permit one transition only, reapply hard constraints to replacement work, and return blocked on mismatch or exhaustion. |
| T-43-06 | Denial of Service | retry/replan path | high | mitigate | Enforce a single replan count and declared cumulative resource limits; never release completed claims or multiply retries. |
| T-43-07 | Elevation of Privilege | Claude/Codex dispatch | high | mitigate | Invoke strategy-bound validation only as an additional gate; preserve `validateInvocation` and `preDispatchGate` immediately before spawn and keep authority/effect/path/runtime checks authoritative. |
| T-43-08 | Spoofing/Tampering | lease checkpoints | high | mitigate | Re-read durable `claimed_actions` through the existing lease store, treat missing/blocked claims as non-spawnable, and preserve runtime/project/lease identity checks. |
| T-43-09 | Information Disclosure | replan/checkpoint data | medium | mitigate | Store identifiers, bounded facts, statuses, and reason codes only; do not persist raw prompts, secrets, environment, or file contents. |
| T-43-SC | Tampering | package installation | low | accept | No package-manager install is planned; all changes use existing modules and Node.js built-ins. |

High-severity threats block dispatch when their mitigation fails, consistent with ASVS Level 1 enforcement.
</threat_model>
