<assumption_delta_decision>
noun: NativeDispatchAdapter
decision: promote
rationale: Phase 38 introduces a SECOND runtime adapter (Claude + Codex) where v1.5 had discovery-only adapters. The general NativeDispatchAdapter contract is promoted to the primary artifact; per-runtime implementations (claude.mjs, codex.mjs) are variants of it. This makes HOST-03's "incompatible adapter disables autonomous dispatch only for that runtime" a structural property: each variant independently reports canDispatch() and recommendation_only without weakening the other. The contract — not any single-runtime impl — is the source of truth.
</assumption_delta_decision>

<objective>
Prove the thinnest end-to-end vertical slice of native host dispatch on the Claude runtime: an authorized harmless fixture is really spawned by a router-owned adapter off the prompt hot path, and a receipt binds an adapter-issued invocation_identity to verifiable completion evidence. This is the load-bearing feasibility proof — if this slice works, the Codex variant (Plan 02) and the budget/bundle work (Plan 03) are mechanical extensions.

Purpose: HOST-01 is the hard feasibility gate. Downstream phases (39-46) build authority, leases, receipts, and learning on this proven boundary; if a real native invocation + attributable receipt cannot be demonstrated on Claude, the v1.6 autonomy architecture blocks and requires redesign.

Output: NativeDispatchAdapter contract, receipt store, Claude dispatch adapter, harmless fixture, minimal off-hot-path trigger in router.mjs, and the anti-cheat test that proves "recommendation text or a test helper alone cannot pass."
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| prompt text → adapter | Untrusted user prompt crosses into router; the adapter must NEVER derive the spawn command from it. |
| adapter → host process | child_process.spawn crosses into the OS; the command/args must be a fixed, validated fixture path. |
| receipt store → receipt readers | Receipts are read by observe() and (in Phase 44) attribution; they must not leak prompt text or secrets. |
| runtime partition | Claude receipts live under ~/.claude/router/receipts/; Codex under ~/.codex/router/receipts/ — no cross-runtime bleed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-38-01 | Tampering/Elevation | adapter spawn command | high | mitigate | Fixture command/args are a fixed, validated path from the lease marker, NOT derived from prompt text. Validate with commandReference/portableTarget/within (src/adapters/claude.mjs:246-289): reject '..', root escape, unsupported tokens. Path must resolve inside repo or ~/.claude/router/. |
| T-38-02 | Spoofing | recommendation text forging a receipt | high | mitigate | Receipts are written ONLY by the adapter process to receipts/ with an adapter-issued invocation_identity (adapter id + pid + adapter version). The prompt path (formatInjection/emit) cannot write receipts. Anti-cheat Test 4 verifies. |
| T-38-03 | Spoofing | test helper masquerading as native invocation | high | mitigate | Receipt requires pid of a process the adapter spawned + stdout_sha256 of that process's stdout. A test helper running the fixture has no adapter-issued pid. Anti-cheat Test 3 verifies. |
| T-38-04 | Information Disclosure | secret/prompt leakage into receipt | high | mitigate | Receipts store only hashes, command, args, exit, wall time, route metadata. Apply redact() (router.mjs:1965-1977) before hashing any prompt-derived field. Never store raw prompt text, env, or file contents. |
| T-38-05 | Denial | hot-path spawn blows latency budget | high | mitigate | Spawn is OFF the prompt hot path (fire-and-forget unref). Perf assertion in acceptance criteria: hook returns <100ms with trigger present. Plan 03's budget test enforces p95<=25ms, p99<=50ms. |
| T-38-06 | Tampering | path-escape via fixture path | high | mitigate | Fixture path validated by within(realpathSync(root), candidate) (src/adapters/claude.mjs:10, 38-48); must resolve inside repo or ~/.claude/router/. Static path, never from prompt input. |
| T-38-07 | Elevation | cross-runtime receipt bleed (Claude receipt authorizes Codex) | medium | mitigate | Receipts partitioned by runtime dir (~/.claude/router/receipts/ vs ~/.codex/router/receipts/ via os.homedir() + detectRuntime()); receipt.runtime field validated on read. Same discipline as v1.5 telemetry (PARITY-02). Plan 02's parity test verifies. |
| T-38-SC | Tampering | (none — stdlib only, no npm/pip/cargo installs this phase) | low | accept | Phase 38 installs no packages (RESEARCH §Package Legitimacy Audit empty); stdlib-only is a hard project constraint. |
</threat_model>
