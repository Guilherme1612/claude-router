# Requirements: Claude Router v1.4

**Defined:** 2026-07-29
**Core Value:** The user can write the minimum useful prompt and still get the best available workflow automatically, with low token overhead, sub-100ms prompt routing, and no per-prompt external classifier.

## v1.4 Requirements

v1.4 is a delta on the shipped v1.3 router. It closes the mode-map coverage gap (only ~18 of ~60 gsd-* workflow modes mapped; ~9 design skills unmapped) and sharpens auto-skill routing via signal_patterns expansion — without adding dependencies, hot-path cost, or mutation risk. Evolution weight tuning is deferred (highest research flag; signal_patterns expansion is the safer primary lever for "auto-use the right skills improves").

### Mutation Safety Infrastructure (prerequisite — must ship before any mode-map/weights mutation)

- [x] **SAF-01**: Cache key includes a `routing_version` derived from mode-map mtime + weights version + manifest mtime; cached routes invalidate when mode-map or weights change.
- [x] **SAF-02**: A cached route whose target id is absent from the current manifest is never served — the route is recomputed instead.
- [x] **SAF-03**: Warm routing p95 stays below 40ms and every measured route stays below 100ms on the calibration corpus after mode-map expansion (regression test, re-run each phase).
- [x] **SAF-04**: `additionalContext` rendering is capped at 1 mode + 3 skills + 2 agents + 1 reasoning line (hard drop-and-log boundary), and `mode-map.json` stays below 30KB.

### Coverage Audit-Guard

- [x] **COV-01**: `build-manifest.mjs` runs a coverage audit immediately after the atomic manifest write and emits `coverage-report.json`.
- [x] **COV-02**: The audit classifies every manifest skill/command/agent into an `expected_*` taxonomy (`gap` / `expected_hook` / `expected_warn_mcp` / `expected_bm25_only` / `expected_phase_internal` / `expected_scope_project`), not a boolean gap check, so intentionally-unmapped capabilities are not noisy false positives.
- [x] **COV-03**: Orphan detection is bi-directional — forward (mode-map entry → manifest still has that capability) AND reverse (manifest → mode-map).
- [x] **COV-04**: A `--strict-coverage` flag exits non-zero on unacknowledged gaps for CI gating; `coverage-baseline.json` records acknowledged-unmapped items so intentional gaps do not fail the gate.
- [x] **COV-05**: The hook emits a one-line staleness reminder when `coverage-report.json` is missing or older than the manifest; it never blocks prompt handling (fail-open).

### Mode-Map Curation

- [x] **MAP-01**: High-value unmapped gsd-* workflow modes (`gsd-ship`, `gsd-new-project`, `gsd-execute-phase`, `gsd-quick`, `gsd-validate-phase`, `gsd-verify-work`, `gsd-resume-work`, `gsd-complete-milestone`, and related lifecycle/flow modes) get mode-map entries authored against intent + output type, not skill names.
- [x] **MAP-02**: Unmapped design skills (`brandkit`, `minimalist-ui`, `industrial-brutalist-ui`, `image-to-code`, `imagegen-frontend-web`, `imagegen-frontend-mobile`, `redesign-existing-projects`, `stitch-design-taste`, `excalidraw-diagram`, `gpt-taste`) get mode-map entries.
- [x] **MAP-03**: New entries pass the existing `validateRouteTargets`; MCP-missing agents stay `warn` tier (never auto-dispatched); a manifest-agnostic synthetic fixture asserts new entries route correctly on a non-gsd manifest.

### Signal Patterns Expansion

- [x] **SIG-01**: `signal_patterns` are expanded on existing and new entries, capped at ≤6 patterns per entry, anchored on output type rather than action verbs.
- [x] **SIG-02**: `mode-map.json` schema bumps to v3 and accepts a backward-compatible signal DSL (plain string OR `{kind,value}` object); v2 plain-string entries still parse and the 159+ existing tests stay green.
- [x] **SIG-03**: A collision lint flags any pattern appearing in more than one entry unless explicitly declared, preventing tier inflation and ambiguous matches.
- [x] **SIG-04**: `T_high` / `T_low` / `M` thresholds are re-derived from the calibration set on the expanded entry list (not left at the v1.3 29-entry calibration).

## Future Requirements

### Evolution Tuning (deferred from v1.4)

- **FUT-05**: Offline `tune-weights.mjs` applies Wilson lower bound + exponential time-decay to `weights.json`, riding the existing canary/rollback rail, with `enabled=false` default.
- **FUT-06**: A counterfactual shadow log records what flat-BM25 would have routed, and a calibration-set regression gate rejects weight sets that underperform the flat-BM25 baseline.
- **FUT-07**: Telemetry-driven `signal_patterns` proposals (advisory, approval-gated, hashed signatures only) and an escape-hatch rate metric in `router doctor`.

### Advanced Routing (v2)

- **FUT-08**: Confidence-tier recalibration from a held-out calibration set (isotonic/Platt), after the calibration set grows beyond the v1.4 10-task size.
- **FUT-09**: Multi-intent / clarification triggers and boundary-aware substring matching, deferred until false-positive collisions appear in telemetry.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Evolution weight tuning in v1.4 | Highest research flag (SIGIR: up to 80% metric loss from weak-signal PRF); ship-disabled-by-default yields no near-term value; signal_patterns expansion is the safer primary lever for the main goal |
| Evolution touching `signal_patterns` or `mode-map.json` | Mutation boundary — evolution must not rewrite the curated brain |
| Auto-deleting stale mode-map entries | Quarantine + report only; never auto-delete (preserves UX-08 lineage from v1.3) |
| Per-prompt LLM, embedding, vector store, or network lookup | Unchanged from v1.0–v1.3: violates latency, privacy, and offline constraints |
| Hot-path schema change or new dependency | v1.4 is stdlib-only, off-hot-path mutation; hot path stays semantically unchanged |
| Confidence-tier recalibration, multi-intent triggers, boundary-aware substring matching | v2 — high complexity / thrash risk, needs telemetry that does not exist yet |
