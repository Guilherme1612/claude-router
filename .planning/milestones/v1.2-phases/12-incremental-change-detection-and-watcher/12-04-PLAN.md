<interfaces>
From `src/registry/build.mjs`:
- `buildFullRegistry(options)` discovers both runtimes and delegates canonical output to `assembleRegistry(acquisition)`.
- `buildIncrementalRegistry(previous, diff, options)` validates lifecycle evidence, replaces only dirty logical-root slices, and delegates to `assembleRegistry`.
- A valid acquisition is `{ claude: { observations, diagnostics }, codex: { observations, diagnostics } }`.

From `src/registry/watcher.mjs`:
- `createRegistryWatcher` calls `reconcile({ roots, previous, current, diff })` before persisting `current` as the new fingerprint baseline.
- `runRegistryWatcher` currently discards that context and calls `buildFullRegistry`; this is the verified bypass to remove.
- Root specs currently use one `path` for both scanning and `fs.watch`; project roots need separate scan and existing-ancestor watch locations so creation of an initially absent `.claude` or `.codex` directory is observable.

From `src/lifecycle/router-lifecycle.mjs`:
- `controllerConfig.project_root` and `scope_id` already reach registry discovery.
- `controllerConfig.roots` currently contains only `claude_global` and `codex_home`; project logical roots must use the adapter-compatible names `project:<scope_id>:claude` and `project:<scope_id>:codex`.
</interfaces>
