# Requirements: Claude Router

**Defined:** 2026-07-07
**Core Value:** Every user prompt routed to the right workflow mode + skills + agents automatically, in <100ms with no external API call — so rework from mis-routed tasks drops without a per-prompt LLM tax.

> **Load-bearing correction (Phase-1 research):** A `UserPromptSubmit` hook can ONLY append `additionalContext` (model-read reminder). The harness does NOT auto-run appended slash commands — there is no `updatedPrompt` field (verified against official docs). So every injection channel is executed by the MODEL (runs the slash, or invokes the `Skill`/`Agent` tool), not the harness. "High-confidence auto-invoke" = a strong model instruction. Requirements below use this corrected mechanic.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Hook Core (HOOK)

- [x] **HOOK-01**: `UserPromptSubmit` hook (`~/.claude/hooks/router.mjs`) fires on every prompt, pure stdlib Node ESM (`.mjs`), zero npm dependencies, no native modules, no external/network calls.
- [x] **HOOK-02**: Hook reads `prompt` + `cwd` from the stdin payload per the official `UserPromptSubmit` contract and appends its output as `additionalContext` only — never modifies the prompt, never uses exit code 2 (block/erase).
- [x] **HOOK-03**: Hook is fail-open — any exception, parse error, or timeout returns the original prompt unchanged (exit 0, no `additionalContext`); routing never blocks a prompt.
- [x] **HOOK-04**: Hook returns within the harness timeout and completes end-to-end in <100ms on a warm call (target ~15–20ms; bound with `timeout: 5` in the settings binding).

### Routing (RTE)

- [x] **RTE-01**: Hand-rolled Okapi BM25 (k1=1.5, b=0.75) scores the prompt against ~244 matchable manifest entries (skills + plugin_skills + agents_store_skills[non-project] + agents + commands); hooks excluded (no description, event-bound).
- [x] **RTE-02**: Tokenizer lowercases, splits on `/[^a-z0-9]+/`, drops stop words + 1-char tokens; scores over the union of `name` + `description` + `summary` per entry; per-query normalization maps raw scores to `[0,1]` so thresholds are comparable across prompts.
- [x] **RTE-03**: `~/.claude/router/mode-map.json` declares task-signal patterns → selected workflow mode + recommended skills + recommended agents + `invoke_kind` (`slash` | `skill` | `agent` | `warn`), spanning the full command inventory: gsd + superpowers + modernize + git + hookify + scaffold + design + ralph-loop.
- [x] **RTE-04**: mode-map.json is drafted from the manifest + setup docs (`gsd.md`, `ralph-loop.md`, `graphify.md`, `superpowers.md`, `misc-skills-and-marketplaces.md`) and **user-reviewed before any auto-routing goes live** (the one unchecked ship-readiness item).
- [x] **RTE-05**: Confidence tiers apply tunable thresholds (`T_high`, `T_low`, `M` — starting `0.6`/`0.3`/`0.2`) stored in mode-map.json: High = top mode `s ≥ T_high` AND beats runner-up by `≥ M`; Medium = `T_low ≤ s < T_high` OR decisive-but-moderate; Low = `s < T_low` OR no pattern matched OR top-2 within tie margin.
- [x] **RTE-06**: LRU intent-signature cache (`~/.claude/router/cache.json`) maps a normalized prompt signature → route; cache hits skip BM25 and route instantly; cache writes are atomic (temp-file + rename) to survive concurrent prompts.
- [x] **RTE-07**: Cache key invalidates when mode-map.json or the manifest changes (mtime folded into the key), so a stale map never serves a cached route.

### Injection (INJ)

- [x] **INJ-01**: High tier injects a strong model instruction to run the selected mode (`Run /gsd-<mode> <args> because <reason>`) **plus** Skill/Agent instructions for the best non-command skills + agents; the reasoning line (why this mode + these skills/agents) is always visible at High + Medium tiers.
- [x] **INJ-02**: Medium tier injects text only (`Recommended: /gsd-<mode>. Skills: X, Y. Agents: Z. Run if fit.`) — no slash instruction, no auto-action; model primed, user decides.
- [x] **INJ-03**: Low / ambiguous tier injects nothing; the prompt passes through untouched.
- [x] **INJ-04**: Injection respects the `invoke_kind` channel per mode-map entry — `slash` → run-the-slash instruction; `skill` → `Use skill <name> because <reason>`; `agent` → `Dispatch agent <name> for <subtask>`; `warn` → MCP-missing warning (no dispatch).
- [x] **INJ-05**: Injected block carries a sentinel marker (e.g. `<!-- router-inject -->`) so re-entry (caveman co-fire or another invocation) is detected and skipped; the hook never duplicates its own output or touches caveman's mode-tracking block.
- [x] **INJ-06**: Per-prompt injected context stays ≤ ~500 tokens (graphify context, when added in Phase 2, counts toward this cap).

### Guards (GRD)

- [x] **GRD-01**: Agents whose `requires_mcp_not_in_manifest` is non-empty (context7/exa/firecrawl/jina/perplexity/ref/tavily) are demoted to the `warn` tier — inject `Agent <name> needs MCP <x> which is not in manifest — wire it first`; never auto-dispatch.
- [x] **GRD-02**: Project-scoped skills (e.g. `impeccable`, `scope: "project"`) are filtered out of global recommendations — filter on `scope != "project"`; agents-store entries treated as project-only when their project field is set.
- [x] **GRD-03**: ralph-loop routing is two-gated: route to `/ralph-loop "<task>" --completion-promise "<verifiable-criteria>"` ONLY when the task has genuine verifiable done-criteria; tasks without it fall back to inline mode (never fabricate a promise — ralph-loop's no-lying rule).
- [x] **GRD-04**: Explicit user override is detected and respected — a `/`-prefix or a named skill/mode in the prompt short-circuits to pass-through and logs `user_explicit`; the router never overrides an explicit user choice.
- [x] **GRD-05**: mode-map entries never reference deny-rule paths (`.env`, secrets); the router never injects instructions that read those paths.

### Coexistence & Install (COX)

- [x] **COX-01**: Hook coexists with caveman's plugin-scoped `UserPromptSubmit` (`caveman-mode-tracker.js`) — both fire in parallel and their `additionalContext` outputs accumulate (verified behavior); router does not duplicate caveman's mode-tracking role and stays within its own injection contract.
- [x] **COX-02**: `settings.json` binding is additive — appends a top-level `UserPromptSubmit` entry pointing at `~/.claude/hooks/router.mjs` (currently no top-level UserPromptSubmit exists; caveman provides it via plugin scope); existing gsd + context-mode + caveman bindings and ralph-loop's Stop-hook are untouched.
- [x] **COX-03**: Install is append-only with a before/after diff audit on `settings.json` (14 existing hook entries + statusline + 4 enabled plugins must remain intact); rollback is a clean revert of the one appended entry.

### Manifest Freshness (MAN)

- [x] **MAN-01**: Missing manifest → pass-through + log a staleness error; never block.
- [x] **MAN-02**: Stale manifest (mtime older than threshold, or `build_manifest.py` changed since last build) → pass-through + inject a one-line reminder `Manifest may be stale — run build_manifest.py`; never auto-rebuild inside the hook (no blocking subprocess).

### Telemetry (TEL)

- [x] **TEL-01**: Append-only `~/.claude/router/telemetry.jsonl` logs, per prompt: timestamp, prompt signature (hash of normalized prompt + intent keywords — never raw prompt text, to avoid persisting secrets/PII), suggested mode, suggested skills/agents, confidence tier, whether graphify was queried, downstream invocations, and an `outcome` field (populated later, Phase 3). — Done in Plan 01-04 Task 1 (commit b915d53); implemented via `redact()` + `promptSignature()` + `logTelemetry()` in `~/.claude/hooks/router.mjs`.
- [x] **TEL-02**: Telemetry writes are atomic (temp-file + rename) so concurrent prompts never corrupt the log. — Done in Plan 01-04 Task 1; implemented as `appendFileSync(path, line, {flag:'a'})` (atomic, each line <4KB < macOS PIPE_BUF 4096) per the RESEARCH §9 design (Pitfall 16).
- [x] **TEL-03**: Schema includes `outcome` and `downstream_invocations` fields from day 1 (unpopulated in v1) so Phase 3 evolution needs no schema migration. — Done in Plan 01-04 Task 1; both fields are `null` v1, asserted by `tests/router.telemetry.test.mjs`.

### Graphify (GRF)

- [x] **GRF-01** (v1 stub): The "should I query the codebase graph?" decision is stubbed via a heuristic (prompt mentions code symbols / files / "how does X work" / refactor / architecture); when the heuristic fires but no graph exists, the graphify branch is skipped and `graph_missing` is logged.
- [x] **GRF-02** (Phase 2): Real conditional graphify query — when the task touches the codebase + structural understanding adds value, query the graph DB (`graphify-out/`) and fold the result into routing + injection, respecting the ≤500-token injection cap.

### Verification (VRF)

- [x] **VRF-01**: A 10-task calibration test (10 representative prompts with defined "right pick" = mode + skills + agents, covering edge cases: ralph-loop two-gate positive/negative, trivial pass-through, Skill-tool channel, design cluster, modernize+agent) is defined and user-approved before calibration. — Done in Plan 01-04 Task 2; fixture committed (9c4bf7a, user-approved).
- [x] **VRF-02**: Phase 1 exits only when the router suggests the right mode + skills + agents on ≥8/10 of the calibration test; if high-confidence auto-routes are wrong, `T_high` is raised (more pass-through) until accurate. — Done in Plan 01-04 Task 3: calibration PASSED 10/10 (≥8/10 gate, exit 0). Option A applied (signal_patterns wired into `buildCorpus` + mode-map ids realigned to gsd-* + `buildKnownNames` refined to drop bare single-word ids) + signal_patterns data-tuned (modernize-assess/gsd-explore/gsd-secure-phase). Thresholds unchanged (0.6/0.3/0.2). See `01-04-SUMMARY.md` → "Task 3 Resolution".

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Evolution (EVO)

- **EVO-01**: `weights.json` weighted BM25 — boosts modes/skills/agents that led to clean runs; decays ones that led to rework (Phase 3, gated on ~2 weeks of telemetry).
- **EVO-02**: Outcome-feedback loop — heuristic auto (downstream `gsd-verify`/`gsd-ship` → good; `gsd-debug`/`gsd-undo`/`gsd-forensics` fired shortly after → bad; next prompt continues same task → good) + optional explicit `bad route` flag; no per-prompt LLM (Phase 3).
- **EVO-03**: Periodic `mode-map.json` mutation proposals from telemetry pattern detection — user approves or auto-applies (auto-apply vs human-gate split is a v2/v3 design decision) (Phase 3).

### Ancestor Reuse (ANC)

- **ANC-01**: Integrate with `gsd-surface` profiles + `find-skills`/`claude-automation-recommender` logic instead of duplicating discovery code — swap the inline discovery step for reuse of at least one existing primitive (Phase 4).

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Per-prompt LLM-judge classifier | Defeats the <100ms / no-API-call efficiency goal — routing would cost more than the rework it avoids. |
| Embedding/vector store | Flat BM25 over ~186–244 short descriptions is sufficient for v1; premature complexity. |
| New autonomous execution loop | ralph-loop (v1.0.0) already provides the loop primitive and is explicitly the seam for this layer; router routes to it. |
| Replacing gsd-autonomous/gsd-progress/gsd-explore/gsd-surface/find-skills/claude-automation-recommender | Router unifies/drives them; preserving working primitives avoids regression. |
| Selecting hooks mid-task | Hooks are event-bound, not invokable — wrong abstraction. |
| `/route` on-demand verbose view (v1) | The gap is automatic per-prompt routing; a command re-introduces the manual step. May be added later, not v1. |
| Auto-rebuild of manifest inside the hook | Would block the hook past ~100ms; staleness handled by a one-line reminder, not rebuild. |
| Product/multi-user support | Personal tool for this one user's setup, at least initially — keeps scope tight. |
| Global recommendation of project-scoped skills (`impeccable`) | Project-scoped to AutomaticTrading; leaking it globally routes the wrong project's skill. |
| Harness auto-running appended slash commands | Not possible — `UserPromptSubmit` can only append `additionalContext`; the model executes. Designing for harness auto-run would build on a false premise. |
| mode-map.json pre-built in this project | Drafting it from the real manifest + setup docs is Phase 1 work, user-reviewed before live — a guessed map would route wrong. |
