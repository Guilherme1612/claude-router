# Requirements: Router v1.7 Runtime Safety and Release Truth

**Defined:** 2026-08-09
**Core Value:** The user can write the minimum useful prompt and still get the best available workflow automatically, with low token overhead, sub-100ms prompt routing, and no per-prompt external classifier.

## v1.7 Requirements

### Dispatch Safety

- [x] **SAFE-01**: A durable work identity is atomically claimed before native execution and cannot execute twice across prompts, workers, compaction, or restart.
- [x] **SAFE-02**: Claude and Codex enforce declared timeout, retry, output, and completion bounds and record truthful bounded outcomes.
- [x] **SAFE-03**: Lease and receipt identifiers are validated and contained beneath runtime-owned roots with private filesystem modes.
- [x] **SAFE-04**: Lease creation and checkpoint mutation are serialized so colliding operations cannot overwrite authority state.
- [x] **SAFE-05**: Claude and Codex provide equivalent durable at-most-once initial dispatch and resume behavior.

### Production Integration

- [x] **PROD-01**: Production routing selects a validated proportional strategy before native dispatch rather than leaving `planStrategy` test-only.
- [x] **PROD-02**: Dispatch, strategy, learning, migration, and every transitive dependency ship in both Claude and Codex installed bundles.
- [x] **PROD-03**: Learning evidence is unique by receipt identity, causally credited, partitioned, and unable to modify authority, risk, permission, or protected effects.
- [x] **PROD-04**: Migration recovery is crash-durable and idempotent for old and new generations, including missing or corrupt active pointers.
- [x] **PROD-05**: Release eligibility consumes fresh version-bound evidence produced by real installed Claude and Codex checks, never caller-supplied success booleans.

### Validation and Release Integrity

- [x] **REL-01**: Deterministic lifecycle, uninstall, lease, watcher-cleanup, and performance regressions are fixed at shared root causes.
- [x] **REL-02**: Cross-phase regression tests describe the current receipt and dispatch contracts without obsolete red-phase assertions.
- [x] **REL-03**: Every v1.7 phase has executable Nyquist validation and current verification evidence with no pass/human-needed contradiction.
- [x] **REL-04**: One minimal automated gate runs focused and full tests, installed-runtime parity checks, archive visibility, and planning projection checks.
- [x] **REL-05**: Milestone audit, canonical planning files, archive artifacts, installed bundles, and the release tag describe the same verified commit.

## Future Requirements

None. New capability work is deferred until v1.7 release truth is established.

## Out of Scope

| Feature | Reason |
|---------|--------|
| New orchestration framework or daemon | Existing Router architecture is sufficient; this milestone closes correctness and integration gaps. |
| External publication or deployment automation | Owner-controlled side effects remain outside Router authority. |
| Broad router.mjs rewrite | Remediation targets shared boundaries with the smallest safe changes. |
| New runtime beyond Claude and Codex | No demonstrated requirement. |
| Cosmetic refactors | Only verified duplication or orphan removal on touched paths is in scope. |
