<objective>
Close verification gaps 1 and 2 by introducing an opt-in, default-off testability seam in the production activation path, then rewriting the lifecycle E2E and recovery test suites to drive the installed watcher→controller→publishCompiledIndex seam (via the seam) instead of fixture-side publication, and to cover the full D-04/D-05/D-06 recovery matrix.

Purpose: The verifier found that tests/router.autonomous-lifecycle.test.mjs lines 65-74 manually call publishCompiledIndex for every safe event, bypassing the installed controller publication seam; and tests/router.lifecycle-recovery.test.mjs only covers two direct publisher/loader scenarios, omitting the required installed-controller recovery matrix. A prior executor run proved the original "test-only" scope is infeasible: the production controller (createRegistryReconciler → produceActivationVerification, 8 gates) only calls publishCompiledIndex after verification.disposition === 'passing' && verification.complete === true, but the production gates return non_passing in the test environment (privacy gate subprocess fails because HOME:<repo> resolves the hook to <repo>/.claude/hooks/router.mjs which does not exist in-project; incremental_full_equivalence fails equivalence_build_failed on first run; the resulting test_only:true verification is rejected by src/registry/activate.mjs trusted() with verification_not_trusted). The same blocker affects gap 2 and 18-05's gap 3. The approved fix is an opt-in testability seam that lets the installed controller publish via the REAL seam in tests without weakening production.

Output: Three production source files extended with the opt-in seam (default-off, prod-unchanged), one new seam regression test, and two rewritten test files that prove the real production seam end-to-end and close the lifecycle + recovery verification gaps.
</objective>
