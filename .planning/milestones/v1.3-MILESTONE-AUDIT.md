Also `mode-map.json` not wired into controller config (`mappings=null`).

**Current codebase + live state (2026-07-28): the mapping-metadata gap is CLOSED.**

1. **`mode-map.json` is now wired into the build.** `src/registry/build.mjs:114-131` defines `resolveModeMapTargets(modeMapPath)`, and `build.mjs:297-331` stamps `mapping.explicit_subjects` onto matching records at build time (union with any artifact-provided mapping; claude-runtime record wins on dual-runtime name collisions to avoid `explicit_authority_conflict`). `~/.claude/router/controller/config.json` now carries `"mode_map_path": "/Users/guilherme/.claude/router/mode-map.json"` (the prior `mappings=null` / `mapping_policy=null` condition no longer holds).
2. **The live candidate registry now carries mapping metadata.** `~/.claude/router/candidate/registry.json` (dated 2026-07-25, post-fix): **22 of 257 records carry `mapping.explicit_subjects`**, covering the 22 workflow targets in `mode-map.json` (`gsd-debug`, `gsd-execute-phase`, `gsd-plan-phase`, `gsd-code-review`, `ralph-loop`, the `gsd-*-agent` agents, etc.). `canonical_identity` / `declared_subjects` / `aliases` remain unset — but the mapper (`src/registry/map.mjs:162-169` `mappingMetadata`) consumes `explicit_subjects` first, so this is sufficient.
3. **An active compiled tuple exists.** `~/.claude/router/release-tuples/active.json` → `{"schema_version":2,"tuple_version_id":"t1-b7180f5c75514967"}`, with a populated `versions/t1-b7180f5c75514967/` directory. `publishCompiledIndex` (`src/prompt/publish-index.mjs:69-101`) has therefore successfully passed its ORC-01 `at least one dispatch route` guard end-to-end at least once. The prior `activation_status=preserved reason=bootstrap_publish_failed` condition is no longer present.
4. **Current watcher status is `recovery_required` / `stale_pointer_sequence`** (`~/.claude/router/controller/status.json`, `disposition: eligible`, `strategy: incremental`). This is a stale-active-pointer recovery trigger — the active tuple's registry bytes (256 KB) no longer match the current candidate fingerprint — NOT the mapping-metadata blocker. The candidate is `disposition: eligible`; an incremental reconciliation cycle will republish. The router can activate end-to-end.

**Coverage note:** only 22/257 records are dispatch routes. This is by design — `mode-map.json` (27 entries) is the workflow brain; the remaining 235 skills/agents/commands without mode-map entries are recommendation-only, not workflow dispatch targets. This is not a gap; it is the intended v1.3 routing surface.

**Verdict:** Production activation can now complete end-to-end. The single most important finding the audit set out to verify is: **the mapping-metadata gap that previously blocked all production activation is closed by Phase 21's `build.mjs` wiring + controller config `mode_map_path`.**
