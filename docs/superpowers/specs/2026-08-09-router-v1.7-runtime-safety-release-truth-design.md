# Router v1.7 Runtime Safety and Release Truth Design

**Date:** 2026-08-09
**Status:** Approved
**Milestone:** v1.7 Runtime Safety and Release Truth

## Goal

Make the v1.6 control-plane capabilities real, bounded, reproducible, and releasable in installed Claude and Codex runtimes. The milestone closes the review findings without adding a second orchestration system or expanding Router authority.

## Scope

### Phase 47 — Dispatch and Storage Safety

- Atomically claim and consume dispatch work so a persistent marker cannot repeat an action across prompt-triggered workers.
- Enforce declared timeout, retry, output, and completion bounds during native execution.
- Validate lease and receipt identifiers, prove path containment, use private filesystem modes, and lock lease creation as one transaction.
- Give Codex the same durable at-most-once resume behavior as Claude.

### Phase 48 — Production Integration

- Wire proportional planning into the production dispatch path.
- Deploy strategy, learning, migration, dispatch, and their transitive modules to both runtime bundles.
- Deduplicate learning evidence and restrict learned changes to an explicit safe-field allowlist.
- Make migration recovery durable, idempotent, and bound to genuine installed-runtime evidence.
- Exercise both installed bundles end to end rather than accepting caller-supplied success booleans.

### Phase 49 — Validation and Release Integrity

- Repair deterministic lifecycle, uninstall, lease, watcher-cleanup, and performance failures at their shared root causes.
- Replace obsolete cross-phase assertions with current contract tests.
- Complete Nyquist evidence for the v1.6-derived behavior covered by this milestone.
- Add one minimal automated release gate for tests, archive visibility, installed-runtime parity, and clean planning projections.
- Archive and tag only after live parser, audit, runtime, and repository evidence agree.

## Architecture

The existing Router remains the only control plane. Phase 47 hardens the shared trust boundaries before Phase 48 connects currently isolated modules to production. Phase 49 validates the assembled system and repairs release truth last, so documentation cannot outrun executable behavior.

```text
prompt marker
    -> atomic durable claim
    -> authority and invocation validation
    -> bounded Claude/Codex adapter
    -> durable receipt and lease checkpoint
    -> causal learning and migration evidence
    -> installed-runtime release gate
```

## Safety Invariants

- Prompt routing remains read-only, fail-open, and below the existing latency ceiling.
- Mutation and execution gates fail closed on malformed, foreign, stale, or escaping state.
- Authority never comes from confidence, historical success, learning, or release metadata.
- One durable work identity can produce at most one native execution.
- Declared resource bounds are enforced, not merely validated structurally.
- Receipt and lease storage stays inside runtime-owned roots with private permissions.
- Claude and Codex parity is demonstrated separately; one runtime cannot attest for the other.
- No milestone completion claim is accepted without current tests, installed evidence, Nyquist validation, audit, and archive visibility.

## Validation Strategy

Each behavior follows red-green-refactor with one smallest regression test at the shared boundary. Phase verification includes focused tests, the full repository suite, installed Claude and Codex bundle checks, lifecycle coexistence/uninstall checks, archive verification, and live GSD parser queries. Environment-sensitive failures are classified explicitly; they are never silently counted as passes.

## Non-Goals

- No new framework, dependency, daemon, or general-purpose job queue.
- No automatic external publication, deployment, credentials use, or destructive action.
- No broad rewrite of the 4,000-line hook during remediation.
- No speculative abstraction for future runtimes.
- No cosmetic cleanup unless it removes a verified orphan or duplication on a touched path.

## Acceptance Criteria

1. Repeated prompt triggers cannot execute the same durable work item twice.
2. A child exceeding time or output bounds is terminated and recorded truthfully.
3. Lease and receipt identifiers cannot escape their owned roots or race an authority overwrite.
4. Claude and Codex resume the same checkpoint at most once across process restart.
5. Strategy, learning, and migration have real production callers and ship in both installed bundles.
6. Duplicate evidence cannot satisfy learning thresholds or mutate protected authority/risk fields.
7. Migration recovery is repeatable and validates real, version-bound installed evidence.
8. Deterministic repository tests, installed-runtime gates, Nyquist validation, audit, roadmap state, archive visibility, and the release tag agree.

## Approved Phase Order

1. Phase 47 — Dispatch and Storage Safety
2. Phase 48 — Production Integration
3. Phase 49 — Validation and Release Integrity

The separation is deliberate: security foundations first, production reachability second, release claims last.
