## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted manifest/plugin/private/learned evidence → contract envelope | Already guarded by classifyEvidence in trust.mjs (Phase 41). Semantic resolution reads only trusted contract field values. |
| Relationship graph → compilation gate (NEW) | compileRelationshipGraph validates the derived graph: native-identity collisions, I/O compatibility, stale targets, missing deps. Failures produce diagnostics, not exceptions. |
| Semantic outcome specification → resolver (NEW) | resolveSemanticOutcome matches by contract fields. Only dispatch-candidate disposition capabilities are returned. evaluateEligibility is the authoritative gate. |
| Assembled registry → prompt hot path | compilation and semantic resolution run at build time inside assembleRegistry. The hook reads the pre-compiled registry. No semantic function is called on the hot path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-42-01 | Elevation of Privilege | resolveSemanticOutcome (semantic.mjs) | high | mitigate | Filter to disposition === 'dispatch-candidate' and run evaluateEligibility on every match. Contract field compatibility is necessary but not sufficient. A recommendation-only capability can never be semantically resolved for dispatch. |
| T-42-02 | Spoofing | compileRelationshipGraph native-identity check | medium | mitigate | Reject same native_type with different stableCapabilityId when no variant edge links them. stableCapabilityId is the unique identity; native_type is a classification. |
| T-42-03 | Tampering | compileRelationshipGraph composition I/O check | medium | mitigate | Validate composition edges: producer outputs and consumer inputs must have non-empty intersection. Unknown-state contract fields make the composition unresolvable. |
| T-42-04 | Repudiation | compileRelationshipGraph ambiguous-tie check | medium | mitigate | Reject ambiguous ties — two equally-ranked semantic matches produce a diagnostic with both candidate IDs, not a silent arbitrary pick. |
| T-42-05 | Denial of Service | compileRelationshipGraph + resolveSemanticOutcome on hot path | high | mitigate | All semantic resolution and compilation runs at build time inside assembleRegistry. No semantic function is imported or called by router.mjs or any hot-path file. Verified by grep: no resolveSemanticOutcome or compileRelationshipGraph call in router.mjs. |
| T-42-06 | Information Spoofing | resolveSemanticOutcome reading untrusted contract fields | medium | mitigate | resolveSemanticOutcome reads only fields with envelope.state === 'known'. Unknown-state fields are never used for matching. classifyEvidence (trust.mjs) already rejects untrusted provenance for authority-critical fields before they reach state 'known'. |
