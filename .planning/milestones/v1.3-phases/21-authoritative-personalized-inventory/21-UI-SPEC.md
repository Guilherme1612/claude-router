# Phase 21 — UI Design Contract

> Visual and interaction contract for the authoritative personalized inventory. Generated by gsd-ui-researcher and approved by gsd-ui-checker.

---

## Experience Boundary

Phase 21 extends the existing `router-control` terminal and JSON inspection surface. It does not add a dashboard, web route, interactive TUI, setup wizard, or capability-mutation control. The interface is read-only and local.

The primary user outcome is: inspect the current authoritative inventory, understand whether it is fresh, and inspect an individual normalized record without exposing secret values or raw authored bodies.

Sources: Phase 21 CONTEXT D-08, D-17; REQUIREMENTS DISC-01 through DISC-08; existing `src/cli/router-control.mjs`.

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual CLI grammar; no shadcn |
| Preset | Not applicable |
| Component library | None |
| Icon library | None; do not use emoji or glyph-only state |
| Font | User terminal monospace; never assume a bundled font |
| Rendering | ANSI-free plain text by default; canonical JSON with `--format json` |

No React, Next.js, Vite, Tailwind, shadcn configuration, frontend component tree, or stylesheet is present. The shadcn initialization gate is therefore not applicable.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | CLI usage |
|-------|-------|-----------|
| xs | 4px | Conceptual minimum between inline label and value |
| sm | 8px | One terminal space between `KEY` and value |
| md | 16px | Two-space indentation for nested human-readable detail |
| lg | 24px | One blank line between major optional sections |
| xl | 32px | Reserved; do not simulate with repeated blank lines |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

Exceptions: terminal output is character-cell based. Use exactly one ASCII space between a field label and its value, no leading indentation for top-level fields, and at most one blank line between sections. Do not align values with variable padding because alignment becomes unstable under narrow terminals and localization.

## Typography

The terminal owns the actual font. These four semantic sizes govern hierarchy when output is presented in documentation or a future renderer; plain-text CLI expresses the same hierarchy through order and uppercase labels.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Detail | 14px | 400 regular | 1.5 |
| Body | 16px | 400 regular | 1.5 |
| Section heading | 20px | 600 semibold | 1.2 |
| Command heading | 28px | 600 semibold | 1.2 |

Exactly two weights are permitted: 400 and 600. CLI output must not depend on bold, italics, underline, or ANSI styling to communicate meaning.

## Color

Plain-text and JSON output are color-independent. The following values are fallback presentation tokens only; the CLI must remain fully understandable when the terminal ignores or remaps color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` | Terminal/background surface |
| Secondary (30%) | `#E6EDF3` | Primary text and field values |
| Accent (10%) | `#58A6FF` | Command heading, selected record identifier, and `current` state only |
| Destructive | `#F85149` | Not used by Phase 21; reserved for future destructive confirmations |

Accent reserved for: the command heading, selected capability identifier, and the exact `current` state label. `reconciling`, `degraded`, `failed`, disabled records, diagnostics, and warnings must use explicit text labels and reason codes rather than color alone.

State semantics in any color-capable renderer:

| State | Required text | Optional color |
|-------|---------------|----------------|
| Current | `STATE current` | Accent blue |
| Reconciling | `STATE reconciling` | Neutral secondary |
| Degraded | `STATE degraded` | Amber `#D29922` |
| Failed | `STATE failed` | Red `#F85149` |
| Disabled record | `ENABLED false` and `DISPATCHABLE false` | Muted secondary |

## Information Architecture

### Inventory summary

Render fields in this order:

1. `COMMAND`
2. `OK`
3. `REASON`
4. `STATE`
5. `ACTIVE_GENERATION_ID`
6. `CANDIDATE_GENERATION_ID`
7. `LAST_COMPLETE_RECONCILIATION`
8. `TRIGGER`
9. `PENDING_CHANGES`
10. `STALE_ROOTS`
11. `UNREADABLE_ROOTS`
12. `RECORD_COUNT`
13. `DIAGNOSTICS`

`STATE` is always one of `current`, `reconciling`, `degraded`, or `failed`. Never substitute vague labels such as `ready`, `error`, `healthy`, or `offline`. A degraded or failed summary must include a machine-stable `REASON` and the affected logical roots without exposing absolute home paths.

### Inventory record

Every inspected record exposes these fields in this order:

1. stable capability ID
2. logical root and relative source path
3. runtime and scope
4. native type and semantic type
5. enabled state
6. dispatchable state
7. lifecycle role
8. invocation form, or explicit `unavailable`
9. content fingerprint
10. adapter and parser version
11. required dependency state
12. container/member provenance
13. identity-continuity evidence
14. diagnostics

Unknown future types display `SEMANTIC_TYPE unknown` and `DISPATCHABLE false`; do not hide them or present them as errors. Disabled records remain fully inspectable and display `ENABLED false` plus the reason their downstream dispatch references were invalidated.

### Runtime/category comparison

Any gap view groups by semantic category first, then lists availability by runtime and scope. It must not title a runtime as the default, preferred, primary, or baseline. Same-named global, user-local, project, and worktree records remain separate rows.

## Interaction Contract

- Default invocation returns a bounded summary, not the entire inventory.
- A user explicitly selects a record by stable capability ID to receive record detail.
- Text and JSON formats expose the same semantic fields and state; JSON keys are stable `snake_case`, and text labels are stable uppercase equivalents.
- Lists and records are sorted deterministically by semantic category, runtime, scope, stable capability ID, then relative source path.
- Long collections are represented by count plus a deterministic bounded preview and a continuation instruction. Never silently truncate.
- A reconciliation in progress does not block inspection. Show the last complete active generation and the candidate generation separately.
- A partial or unreadable scan never replaces the displayed last complete inventory. Show `STATE degraded`, affected logical roots, and the next automatic recovery action.
- Inspection never starts reconciliation implicitly unless the command contract explicitly says it is a refresh action. A read-only inventory command has no side effects.
- Exit status is success only when the requested inspection completed. `degraded` may still be inspectable and returns `OK true` with a degraded reason; malformed state, missing required files, or privacy-safe projection failure returns `OK false`.
- Every non-current state includes a reason and an actionable next step. Do not expose internal stack traces by default.

## Privacy and Trust Presentation

- Show logical root labels and relative paths; redact absolute home, project, and worktree prefixes by default.
- Never display raw instruction bodies, configuration bodies, capability-authored prose, environment values, credentials, tokens, or arbitrary MCP payloads.
- Show fingerprints as bounded identifiers: first 12 hexadecimal characters in text; full value may appear in JSON when it contains no secret material.
- Capability-authored labels and descriptions are visibly evidence, never Router policy. They cannot visually override `enabled`, `dispatchable`, scope, lifecycle role, or diagnostic fields.
- Unsafe symlink, scope escape, cycle, malformed artifact, unreadable root, and unsupported-schema observations appear as diagnostics with stable reason codes. Excluded unsafe artifacts never appear as trusted inventory records.
- Diagnostic copy names the logical root and relative path where safe, the reason for exclusion, and whether the last complete snapshot was retained.

## Responsive Terminal Behavior

| Width | Contract |
|-------|----------|
| 120+ columns | One `KEY value` pair per line; bounded JSON values remain on the same line |
| 80–119 columns | Same grammar; long structured values serialize compactly and may wrap naturally |
| Below 80 columns | Preserve labels and full scalar values; summarize collections by count and offer JSON output |

Never use a multi-column table for capability records. It would clip paths, provenance, and diagnostics in ordinary terminals. Never rely on cursor control, terminal detection, or interactive paging.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA / command description | `Inspect inventory` |
| Current success | `Inventory is current.` |
| Reconciling state | `Inventory reconciliation is in progress. Showing the last complete inventory.` |
| Empty state heading | `No installed capabilities found` |
| Empty state body | `No supported artifacts were found in the authorized Claude or Codex roots. Check the configured roots, then run inventory inspection again.` |
| Degraded state | `Inventory may be stale for {logical roots}: {reason}. The last complete inventory is still active; authoritative reconciliation will retry automatically.` |
| Failed state | `Inventory inspection failed: {reason}. The last complete inventory remains active. Check the reported diagnostic and retry inspection.` |
| Unknown type | `Retained as an unknown, non-dispatchable capability.` |
| Disabled record | `Installed but disabled. This capability and affected dispatch references are not eligible for routing.` |
| Redaction notice | `Sensitive values and raw authored content are redacted.` |
| Destructive confirmation | `Not applicable — Phase 21 provides no destructive inventory action.` |

Copy rules:

- Use direct factual sentences, not celebratory or alarming language.
- Name the state, reason, retained safe behavior, and next action in that order.
- Do not call a partial inventory `current`.
- Do not describe an unknown type as invalid merely because Router cannot interpret it.
- Do not suggest that discovery grants permission or dispatch eligibility.

## Component Inventory

| Component | Required content | Behavior |
|-----------|------------------|----------|
| Command envelope | `COMMAND`, `OK`, `REASON` | Reuse existing canonical `router-control` envelope |
| Inventory summary | state, generations, freshness, roots, counts | Default bounded view |
| State line | exact state plus reason | Never color-only |
| Capability record | complete D-17 allowlisted projection | Selected by stable ID |
| Diagnostic entry | code, logical root, safe relative path, message, retained-baseline flag | Stable order and bounded text |
| Gap group | semantic category, runtime/scope availability | Category-first, framework-neutral |
| JSON projection | same information as text | Canonical, stable, machine-readable |

## Accessibility and Automation

- Plain text remains the canonical human surface and must pass without color, Unicode, pointer input, or terminal interactivity.
- All labels are explicit and screen-reader-friendly when terminal output is read linearly.
- Status changes are represented by complete output snapshots, not animation, spinners, or transient cursor updates.
- JSON output is the automation contract; adding presentation fields must not reorder or rename existing semantic keys without a schema/version decision.
- User-provided terminal width, runtime names, paths, and capability names must not break framing or inject extra control sequences. Escape control characters in text and JSON.
